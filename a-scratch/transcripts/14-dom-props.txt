How bindings behave now (src/framework/core/js/FluidView.js)
- Raw values: an attribute whose template is a single reference, like disabled="@{busy}", now gets the actual value instead of a string, so booleans work.
- Absence: false, null, undefined or an unavailable value removes the attribute.
  - Boolean attributes such as disabled, checked and hidden are written as "" when true, and a bound string "false" counts as false.
  - aria-* attributes are the exception: false is written as "false", because that value is meaningful for accessibility.
- Live state: for value, checked, selected, open and indeterminate, the binding sets both the attribute (so the HTML stays accurate) and the DOM property (so the screen agrees). Clearing an input is now just setting the model to "".
  - A textarea value is written as its text content, and the reconciler leaves its children alone.
  - A select value is written as selected on the matching option, and is reapplied after the options are re-rendered.
- Write-back: a listener on input, change or toggle writes the user's change to the bound model value. If the target is a $compute, nothing is written back and only the attribute is updated to match the screen.
- Static attributes and attribute removal go through the same code, so removing value or checked also clears the property.

Tests: one new test in FluidViewTests.js (26 checks) covers each of the cases above, including writing into a $reactiveRoot. Behaviour changes and limits:
- A single reference that is null or undefined now removes the attribute instead of rendering "".
- An unavailable attribute value no longer writes error markup into the element; the attribute is just absent.
- Write-back has the same limitation as the proxy's set (the "follow fish upstream" TODO): when bound through a member that is itself a reference, the value is written on the component that holds the reference rather than at its source. That's why the storyImageGen input binds {storyTime}.state.imagePrompt directly.
- Values typed into an input come back to the model as strings.
- Radio groups aren't handled: when one radio is selected, the others change without firing events.
