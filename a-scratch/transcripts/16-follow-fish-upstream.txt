● Issue #16 is done in both demos. item.todo.completed = … now writes upstream
  to {todoList}.todos.N, including through the filter() projection in the
  assignees version. The full suite passes (965/965, up from 813) and lint is
  clean. I haven't run anything in a real browser.

  The core change (FluidIL.js)
  - What was wrong: with the field copies removed, item.todo returned the raw
    data object. The local toggle method you added was mutating the source data
    in place, so nothing re-rendered.
  - Writes: the proxy's get handler now follows the $sitedRef chain to its end.
    If that lands in reactive material, it hands back a proxy onto that site, so
    the existing set handler writes to the right place. Assigning item.todo = x
    itself still only rebinds the item's own member, the same way JS object
    references behave.
  - Delete (extra credit): delete item.todo follows the same chain and splices
    the array element, or removes the object key, in the source data. Deleting a
    top-level member of a component throws an error.
  - Filter: $for now keeps the site of any element that is itself a proxy. Plain
    Array.prototype.filter over proxied elements already returns proxies, so I
    deleted fluid.wrapFilter and the "filter" branch entirely.
  - Named contexts: {todoItem} used to arrive in method/effect arguments as a
    bare component, so writes through it went nowhere. It's now proxied the same
    way {self} is.

  Demo changes
  - Copies removed: in both todoLists I removed the text/completed copies and
    the global toggleItem/deleteItem. Templates now use
    @{todo.text}/@{todo.completed}, and items use local toggle() and remove()
    methods.
  - Assignees: assignItem and the selectEffect are gone. The item's select
    overrides UISelect's updateSelection to write todoItem.todo.assignee
    directly. This also fixes a real bug: delete and assign used to act on the
    filtered index, so they hit the wrong item whenever a filter was active.

  Tests: new drivers tests/framework-tests/demos/html/TodoListTests.html and
  TodoListAssignTests.html load the actual demo SFCs through
  <fluid-module>/<fluid-import>. They're registered in package.json. They cover
  toggling, direct writes, deletes and index sliding, inserts, filtering,
  provenance checks, and assignment and assignee filtering through the filter.
  With proxyUpstream disabled, the toggle, write, delete and insert tests fail.

  Other bugs fixed along the way
  1. SFC tag layer order (from #15): fluid.sfcViewComponent was prepended to
     $layers, which breaks C3 when another listed layer is also an SFC. The
     assignees demo couldn't instantiate filterCompleted at HEAD. It now goes
     last. I updated the PTF test expectations to match and added a test for a
     derived SFC.
  2. Stale context resolution: when a child component registered itself in its
     parent's scope, contexts already resolved at the parent, like {filters …},
     were never re-evaluated. The parent is now notified.
  3. fluid.module.resolveRelativePath counted the document's filename as a
     directory, so %todoApp/css/bulma.css broke on any page URL ending in a
     filename like index.html.
  4. Empty <style></style> was treated as a stylesheet link with an undefined
     href.
  5. Test harness: fqunit-html now sets readyState, fires DOMContentLoaded, and
     fires load/error on stylesheet links, so bootDocument and SFC style imports
     work under node.
