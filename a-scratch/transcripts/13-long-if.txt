I've added a long-form $if record for issue #13. A record like $if: {func: x => x > 0, args: "{closestNoteFinder}.hasDistance"} now controls whether the component is created. The full npm test run passes (735/735) and eslint is clean on the changed files. The demo I changed hasn't been tried in the browser. Nothing is committed yet.

How it works (src/framework/core/js/FluidIL.js)
- A new function, fluid.expandIfRecord, handles the condition. A string is still treated as a context reference, as before.
- An object is treated as a func/args record and turned into a computed value the same way $compute records are, so func can also be a global function name or a context reference. The component is created when that value is truthy.
- expandComponentRecord now calls fluid.expandIfRecord instead of fetching the reference directly.
- I also fixed a small bug nearby: the debug name of the conditional cell used ${segs.join} without calling it, so it printed the function's source code rather than the path.

Test (tests/framework-tests/core/js/FluidViewTests.js)
- The new test uses $if: {func: x => x !== null, args: "{longFormIf}.distance"}. It checks that a distance of 0 shows the block, that the value updates, and that null hides it again.

Demo and notes
